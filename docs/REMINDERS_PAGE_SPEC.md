# 提醒事项页面 SPEC

> 适用范围：Petsona 桌面版管理面板的「提醒事项」页，以及它关联的待提醒数据域、桌宠气泡处理、每日统计页。
>
> 本 SPEC 定义 MVP 目标与约束。实现阶段应先满足这里的闭环，再考虑音效、云同步、月历、趋势图等扩展。

## Problem Statement

当前 Petsona 已具备基础提醒能力：番茄钟、喝水、站立、免打扰、调度器、桌宠气泡，以及一个临时的 Todo 区。但现有体验还不是一个完整的「提醒事项页面」：

- 用户不能在一个页面里直观看到四类核心提醒的状态。
- 待提醒 Todo 仍偏临时存储，缺少正式的数据模型、重复规则、编辑、每日重置和历史统计。
- 到点提醒、用户完成、稍后提醒、统计记录之间还没有形成闭环。
- 用户想知道「今天 Petsona 提醒了我多少次、我完成了多少」时，没有按日期查看的统计页面。
- 视觉上需要参考用户提供的暖色卡片式提醒页，但必须压进当前主面板尺寸，而不是照搬大屏手机稿。

提醒事项页的目标不是做一个通用日历或复杂任务管理器，而是成为 Petsona 的个人提醒控制台：用户可以快速开关/设置日常提醒、管理待提醒事项，并通过桌宠温和地完成提醒闭环。

## Proposed Solution

### 总体方案

采用「提醒控制台 + 本地提醒数据域 + 统计历史闭环」方案。

本次 MVP 一起交付：

- 四张固定提醒卡片：番茄钟、喝水提醒、站立提醒、免打扰时段。
- 待提醒列表：支持新增、编辑、完成、删除、重复规则。
- 桌宠气泡闭环：提醒到点后气泡显示，并提供「完成」和「稍后提醒」。
- 每日提醒实例：每天 00:00 生成今日实例，软件启动时补齐当天实例。
- 统计页：按日期展示已提醒数、已完成数、完成率，点入查看当天详情。
- 本地正式数据域：提醒配置、待提醒模板、今日实例、历史统计统一持久化。

### 页面布局

提醒事项页继续作为管理面板内的子页，适配当前主面板约 `440px` 宽、贴内容的窄窗口。

页面参考用户提供的视觉稿，但按 Petsona 当前面板重排：

- 背景：温暖米白色。
- 主色：深棕文字、柔和浅棕/米色卡片、白色设置按钮、浅色状态 chip。
- 顶部：固定 `2 x 2` 小卡片网格。
- 下方：标题为「待提醒」的列表区域。
- 底部：居中圆形渐变加号按钮，用于新增待提醒。
- 整页允许纵向滚动；顶部四卡必须完整展示，待提醒区根据剩余高度展示 3-5 条，更多内容向下滚动。

不要求一比一照搬参考图。必须优先保证当前主面板尺寸下的可读性、按钮可点性和文字不溢出。

### 四张提醒卡片

固定四项：

1. 番茄钟
2. 喝水提醒
3. 站立提醒
4. 免打扰时段

卡片内容：

- 标题。
- 当前配置或状态值。
- 状态按钮：开始/停止、开启/关闭、进行中/已关闭等。
- 「设置」按钮。

默认值：

- 番茄钟：专注 `25` 分钟，休息 `5` 分钟。
- 喝水提醒：每 `60` 分钟。
- 站立提醒：每 `45` 分钟。
- 免打扰时段：`22:00-09:00`。

卡片交互：

- 点击状态按钮可直接开始/停止或开启/关闭。
- 点击「设置」打开轻量设置弹窗。
- 设置弹窗只改核心参数：
  - 番茄钟：专注时长、休息时长。
  - 喝水：间隔分钟。
  - 站立：间隔分钟。
  - 免打扰：开始时间、结束时间。
- MVP 不支持自定义卡片、新增卡片、删除卡片、卡片排序。

### 待提醒列表

列表标题显示为「待提醒」，不显示英文 `Todo`。

待提醒是「带提醒时间的任务」，不是普通无时间 Todo。

每条待提醒支持：

- 任务内容。
- 提醒时间。
- 重复规则：
  - 一次性。
  - 每天。
  - 每周指定星期。
- 完成状态。
- 删除。
- 编辑任务内容、提醒时间、重复规则。

新增入口：

- 点击底部圆形加号按钮。
- 打开轻量新增弹窗。
- 新增弹窗字段：任务内容、提醒时间、重复规则。

编辑入口：

- 点击任务行或编辑入口。
- 复用新增弹窗。

完成与删除：

- 勾选后保留在当天列表中，显示已完成状态。
- 删除前必须二次确认。
- 删除一个重复提醒只影响今天之后，不改写过去统计记录。

排序规则：

- 未完成在上。
- 未完成项按下次提醒时间从近到远排序。
- 已完成项沉到底部。

空状态：

- 首次没有真实待提醒时，可以展示 2-3 条空状态示例，帮助页面看起来完整。
- 示例不写入真实数据。
- 用户新增真实待提醒后，显示真实列表。

### 每日重置与提醒实例

待提醒应区分「模板」和「每日实例」：

- 模板：用户创建的提醒规则，例如「每周三 17:55 倒垃圾」。
- 今日实例：某一天根据模板生成的具体提醒记录，例如「2026-07-04 17:55 倒垃圾」。

重置规则：

- 每天 `00:00` 生成当天实例。
- 如果软件在 `00:00` 没有运行，启动时补齐当天实例。
- 一次性提醒完成或过期后不进入新一天。
- 每天重复和每周重复提醒按规则在新一天重新出现。
- 过去记录不因后续编辑或删除而变化。

错过规则：

- 到点已提醒但未完成的事项，当天仍保留。
- 状态标记为「已错过」或等价的未完成过期状态。
- 不自动顺延到第二天补弹。
- 统计页应能体现「已提醒但未完成」。

### 桌宠气泡提醒

MVP 提醒触发方式：

- 只弹桌宠气泡。
- 不播放提示音。
- 不发 macOS 系统通知。

气泡操作：

- 「完成」：将对应提醒实例标记为完成，写入完成时间，并进入统计。
- 「稍后提醒」：固定 `10` 分钟后再提醒一次。

音效是后续扩展方向。MVP 只预留数据/设置扩展空间，不展示不可用的声音开关。

### 统计页

统计页纳入本次 MVP。

入口：

- 放在提醒事项页标题右侧。
- 使用小图标或轻量按钮进入，不抢占主内容。

第一层：日期列表卡片

- 默认展示最近 `30` 天。
- 本地长期保留历史数据。
- 每天一行，展示：
  - 日期。
  - 已提醒数。
  - 已完成数。
  - 完成率。
- 点击某天进入详情。

第二层：单日详情页

展示该日任务明细和状态时间线：

- 提醒标题。
- 提醒类型：番茄钟、喝水、站立、待提醒、免打扰记录。
- 提醒时间。
- 是否完成。
- 完成时间。
- 重复规则标记：一次性、每日、每周。

统计范围：

- 顶部四卡产生的提醒。
- 用户创建的待提醒列表。

完成口径：

- 喝水/站立：用户点气泡「完成」才算完成。
- 番茄钟：一个专注周期结束算完成。
- 待提醒：用户勾选完成或在气泡点「完成」算完成。
- 免打扰：记录开启状态/时段，不计入完成率。

统计口径：

- 「已提醒」表示当天实际触发过提醒。
- 「已完成」表示用户或系统按对应口径完成。
- 完成率 = 已完成 / 可计入完成率的已提醒数。
- 免打扰记录可在详情里展示，但不进入完成率分母。

## Technical Constraints

### 平台与窗口

- 当前目标平台是 macOS 桌面版。
- 页面运行在 Tauri 管理面板内。
- 当前主面板贴内容，参考尺寸约 `440 x 640`，不得按大屏 dashboard 设计。
- 页面必须在窄宽度下保持可读；文字不得溢出按钮、卡片或列表行。
- 允许页面纵向滚动。

### 架构边界

- 协议类型的唯一真源是 `packages/shared`。
- 契约变更应先定义共享类型，再改壳、harness 或 UI。
- 本地数据必须遵守 `$DATA/<userId>/` 命名空间。
- 不继续把待提醒和统计堆在临时 `localStorage` 作为长期方案。
- MVP 需要建立正式本地数据域，至少覆盖：
  - 提醒模板。
  - 每日提醒实例。
  - 提醒事件记录。
  - 日期统计摘要。
- 历史记录不可被后续模板编辑反向改写。

### 调度与提醒

- 应复用现有 M3 调度器、30 秒 tick、勿扰/全屏静默守卫和桌宠气泡能力。
- 喝水、站立、番茄钟应继续与现有 `REMINDER_SET/STOP` 能力兼容。
- 待提醒列表的气泡不应只依赖 UI 域轮询；实现阶段应把它接入正式提醒数据域。
- 面向用户的提醒文案应走 persona 出口或兜底文案池，不散落硬编码。
- MVP 不接 macOS 系统通知权限。
- MVP 不播放声音。

### 弹窗与交互

- 管理面板内禁止使用 `window.prompt`、`window.confirm`、`window.alert`。
- 新增、编辑、删除确认、卡片设置都必须使用面板内自绘弹层能力。
- 删除必须二次确认。
- 「稍后提醒」固定 10 分钟，不做多选项。

### 数据一致性

- 所有提醒实例必须有稳定 ID。
- 重复模板和每日实例必须能关联，但实例要保留创建当日的标题、时间、重复标签快照。
- 删除或编辑模板只影响今天之后，不能改写历史详情。
- 软件跨天运行时要生成新一天实例。
- 软件跨天未运行时，启动后要补齐当天实例。
- 错过提醒不补弹到第二天。

### 测试约束

实现阶段至少需要覆盖：

- 四张固定卡片的默认值、开启/关闭、设置更新。
- 待提醒新增、编辑、删除确认、完成、排序。
- 一次性、每日、每周指定星期的今日实例生成。
- 跨天重置与启动补齐。
- 错过提醒保留为未完成/已错过。
- 气泡「完成」写入完成时间。
- 气泡「稍后提醒」生成 10 分钟后的再提醒。
- 统计页最近 30 天列表、单日详情、完成率计算。
- 免打扰记录不进入完成率分母。

## Non-goals

MVP 明确不做：

- 自定义顶部卡片数量、名称、排序。
- 月历视图。
- 趋势图、周报、月报。
- 云同步或多设备同步。
- macOS 系统通知。
- 提示音效播放与声音设置。
- 完整日历/日程管理。
- 工作日、自定义间隔、每月重复等复杂重复规则。
- 拖拽排序待提醒。
- 批量操作。
- 导出统计数据。
- 把提醒统计和健康分析做成复杂仪表盘。

## Success Criteria

MVP 完成后，应满足以下验收标准：

1. 用户打开「提醒事项」页时，能在当前主面板尺寸下一眼看到四张提醒卡和「待提醒」列表，视觉贴近参考图但不拥挤。
2. 用户能直接从四张卡片开始/停止或开启/关闭提醒。
3. 用户能通过卡片设置弹窗修改番茄钟、喝水、站立、免打扰的核心参数。
4. 用户能新增、编辑、完成、删除待提醒。
5. 待提醒支持一次性、每天、每周指定星期。
6. 待提醒按「未完成优先、下次提醒时间从近到远、已完成沉底」排序。
7. 到点后桌宠气泡会提醒用户，并提供「完成」和「稍后提醒」。
8. 点击「完成」会更新今日列表和统计记录。
9. 点击「稍后提醒」会在 10 分钟后再次提醒。
10. 每天会生成新的今日提醒实例；软件未运行时，启动后会补齐当天实例。
11. 已提醒但未完成的事项当天保留为未完成/已错过，不自动顺延到第二天补弹。
12. 统计入口可从提醒事项页进入。
13. 统计页默认展示最近 30 天，每天显示已提醒数、已完成数、完成率。
14. 点击某天能看到当天每条提醒的标题、类型、提醒时间、完成状态、完成时间、重复标记。
15. 喝水/站立/待提醒只有用户完成后才计入完成数；番茄钟专注周期结束计入完成；免打扰不计入完成率。
16. 重启 App 后，提醒模板、今日实例、完成记录、统计历史仍然保留。
17. 页面内所有弹窗使用自绘弹层，不调用浏览器原生 prompt/confirm/alert。
